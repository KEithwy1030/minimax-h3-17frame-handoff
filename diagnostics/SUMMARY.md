# 这次量到的结果

后一次复测见文末「会闪运行」。上面各节里用官方权重解的是 `seg_0000`，不是会闪的那次 latent。

只记测到的数。实验 2–5 用的是官方 `Ref2VA/video_vae/source/model.safetensors`（10415548320 字节，读入后 fp16），空间是整份 latent `[1, 24, 37, 38, 66]`，不是中心 8×8。亮度是全帧 BT.601 Y 的平均值，范围 0–255。相对变化是 `(当前帧 - 前一帧) / 前一帧`。

## 实验 1

`seg_0000.av.pt` 的视频 latent 在反归一化前后都有按 5 个时间下标重复的幅度差。`t % 5 == 0` 和 `t % 5 == 1` 接近，然后升到 `t % 5 == 4`。反归一化前，这两组的 L2 平均是 210.48 和 210.71，`t % 5 == 4` 是 260.93。反归一化后 L2 平均分别是 449.14、475.94、619.28。

## 实验 2

ComfyUI 和官方 `decode_temporal` 的切片公式一致，实际调用也一致：7 次，每次 7 个 token、解码 28 帧。每块丢掉的局部帧下标是 0、1、2、20、21、22。写出的成片帧是 0–16、17–33、34–50、51–67、68–84、85–101，最后一块再写出 102–118 和 119–123。`pad_tokens = 0`，两边都是 124 帧。

用这份官方权重解同一份 latent，接缝处没有大约 30% 的亮度下跌。ComfyUI 第 17 帧相对第 16 帧是 70.91 → 70.50（-0.57%），第 34 帧是 70.84 → 69.93（-1.28%）。官方解码对应是 70.89 → 70.48（-0.58%）和 70.82 → 69.92（-1.28%）。124 帧里两边亮度差的绝对值最大 0.0178，平均 0.0166。

## 实验 3

官方权重下完整了。`frame_luma_full_decode.csv` 是官方 `AutoencoderKLLegacy.decode_temporal` 的 124 帧。第 17、34、51、68、85、102、119 帧相对前一帧的变化是 -0.58%、-1.28%、-0.61%、-1.22%、-0.44%、-1.08%、-0.68%。

## 实验 4

在同一份官方权重、同一份 latent 上，给每块多带前 2 个 latent token，没有把接缝变得更平。第 17 帧仍是 -0.57%。从第 34 帧起，原版大约 -0.4% 到 -1.3%，带上下文后是 -5.24% 到 -7.01%。没有一帧达到 -15%。ComfyUI 的 `vae.py` 没有改。

## 实验 5

静止图是 `h3_watch_stock_00001_.png`，缩成 128×128，重复 124 帧。256×256 的整段一次编码占满 12GB 显存，20 分钟没有返回，这三种往返没有 256 的结果。权重仍是上面的官方文件。

- 整段一次编码再一次解码：latent 时间长度 31，成片 124 帧。相对下降超过 15% 的帧是 12（-22.9%）、16（-33.2%）、100（-19.6%）、104（-29.5%）。第 17 帧相对第 16 帧是 +0.93%。
- 按 17 帧分段编码，再用原版 `decode_temporal`：124 帧，最大的帧间下降是 -1.23%。第 17、34、51、68、85、102、119 帧都是 40.24 → 39.91（-0.81%）。
- 分段编码后再用带 2 token 上下文的解码：第 17 帧是 -0.81%。第 34、51、68、85、102、119 帧都是 56.60 → 39.48（-30.26%）。这项预热帧对齐有误，结果不可用。

## 会闪运行

`comfy/sd.py` 恢复成 `8a33128` 之后，22 帧 pruned 工作流的 VAEDecode 输出仍然闪。第 16→17 帧全帧 Y 从 61.01 到 42.44，下降 30.4%。16 个 4×4 分区全部变暗。同一份 latent 用官方权重解码，第 16→17 帧从 57.86 到 57.48，下降 0.66%。这份 latent 不是 `seg_0000`。
